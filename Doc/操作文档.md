根据日志分析，报错的原因是**MyBatis Plus查询返回了多条数据，但代码期望只返回一条（或null）**。

## 核心错误

```
org.apache.ibatis.exceptions.TooManyResultsException: Expected one result (or null) to be returned by selectOne(), but found: 2
```

## 错误位置

在 `SensorConfigServiceImpl.java` 的第136行，调用了 `selectOne()` 方法，但数据库查询条件匹配到了 **2条记录**，而 `selectOne()` 要求结果必须为0或1条。

## 调用链路

1. MQTT消息到达主题 `eduBox/device/examConfig`
2. → `SensorMqttController.getSensorThresholdConfig()` 处理
3. → `SensorConfigServiceImpl.updateThresholdFromMqtt()` 
4. → `BaseMapper.selectOne()` 查询数据库
5. → 查询条件匹配到2条记录 → 抛出异常

## 解决方案

### 1. 检查业务逻辑（推荐）
查看 `SensorConfigServiceImpl.java:136` 的查询条件，确认：
- 查询条件是否应该更精确（比如增加 `source` 和 `sensor` 的组合条件）
- 是否应该使用 `selectList()` 然后取第一条，或处理多条数据

### 2. 修复数据（临时方案）
检查数据库表，找出为什么会有2条记录匹配同一个条件：
```sql
-- 查看匹配的记录
SELECT * FROM 你的表名 WHERE [查询条件];

-- 如果确实不应该有重复，删除或更新多余的数据
```

### 3. 修改代码（根本方案）
如果业务上允许存在多条记录，应该改用 `selectList()`：
```java
// 原代码（第136行附近）
Entity entity = mapper.selectOne(queryWrapper);

// 修改为
List<Entity> list = mapper.selectList(queryWrapper);
if (CollectionUtils.isNotEmpty(list)) {
    // 处理第一条或全部
    Entity entity = list.get(0);
}
```

## 建议
先检查数据库，确认是否有重复数据，以及这些数据的业务含义是否合理，再决定是清理数据还是修改代码逻辑。

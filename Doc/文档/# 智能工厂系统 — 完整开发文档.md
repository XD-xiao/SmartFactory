## 1. 项目概述

智能工厂系统是一个面向制造业的数字化管理平台，分为三个代码仓库：

| 模块 | 仓库路径 | 说明 |
|------|----------|------|
| **SmartFactoryService** | `SmartFactoryService/` | 后端服务，Spring Boot 4.0，提供 REST API、MQTT 通信、WebSocket 推送 |
| **SmartFactoryWeb** | `SmartFactoryWeb/` | 前端应用，Vue 3 + Vite，提供管理后台、大屏展示 |
| **Doc** | `Doc/` | 设计文档、数据库脚本、接口设计、MQTT 设计 |

**核心业务模块**：

| 模块 | 说明 |
|------|------|
| 设备管理 | 设备 CRUD、设备分组、PLC 产线设备、维修故障管理 |
| EduBox 传感器 | 教育实验箱管理，支持 11 种传感器的配置与数据记录 |
| 人员管理 | 员工、部门、岗位、考勤打卡、请假审批 |
| 产品管理 | 产品类型、产品型号、产品信息、生产计划、出入库管理 |
| Agent 智能检测 | AI 驱动的预测性维护与异常检测，定时分析传感器数据并生成检测报告 |
| 大屏展示 | 实时数据看板，设备状态、人员考勤、产品产量、传感器数据 |

```
                              │

┌─────────────────────────────────────────────────────────────────┐
│                         数据层                                   │
│  ┌──────────────────┐    ┌──────────────────┐                   │
│  │   MySQL 8.0       │    │   MQTT Broker     │                  │
```

**数据流**：
1. **HTTP/HTTPS**：前端通过 Axios 基于 REST API 与后端交互，请求头携带 JWT Token 认证
2. **MQTT**：后端通过 MQTT 协议与 IoT 设备双向通信，订阅设备上报数据，发布控制指令
3. **WebSocket (STOMP)**：后端定时任务通过 WebSocket 向前端大屏推送实时数据（人员、产品、产线、传感器）

### 5.1 分层架构

项目采用经典的四层分层架构：**Controller → Service → Mapper → Entity**，通过 Spring 依赖注入实现解耦。

```
┌─────────────────────────────────────────┐
│             Controller 层                │
│  HTTP REST (@RestController)             │
│  MQTT Handler (@MqttController)          │
│  WebSocket (@MessageMapping)             │
└────────────────┬────────────────────────┘
                 │
┌────────────────▼────────────────────────┐
│              Service 层                  │

└────────────────┬────────────────────────┘
                 │
┌────────────────▼────────────────────────┐
│              Mapper 层                   │
│  MyBatis-Plus BaseMapper<T>             │
│  数据库 CRUD 操作                         │
└────────────────┬────────────────────────┘
                 │
┌────────────────▼────────────────────────┐
│              Entity 层                   │
```

`LoginCheckInterceptor` 实现了 JWT 鉴权流程：

```
请求进入 → preHandle()

  ├── Token 解析失败 → 返回 401
  └── Token 有效 → 解析 claims 存入 UserContext（ThreadLocal），放行
```

### 5.11 自定义 MQTT 框架

项目构建了一套**类似 Spring MVC 的注解驱动 MQTT 消息路由框架**。

#### 5.11.1 核心注解

| 注解 | 作用目标 | 说明 |
|------|----------|------|
| `@MqttController` | 类 | 标记为 MQTT 消息控制器（组合了 `@Component`） |
| `@MqttSubscribe` | 方法 | 声明订阅的 Topic 列表，支持 MQTT 通配符（`+` 单层、`#` 多层） |
| `@MqttTopic` | 参数 | 注入当前消息的 Topic 字符串 |
| `@MqttPayload` | 参数 | 注入消息 Payload，自动通过 FastJSON2 反序列化 |

#### 5.11.2 核心组件

| 组件 | 职责 |
|------|------|
| `MqttSubscriptionTopicCollector` | 扫描所有 `@MqttController` 类，收集 `@MqttSubscribe` 的 Topic 列表 |
| `MqttHandlerMethodRegistry` | 注册所有 MQTT 处理方法，建立 Topic → Handler 映射，校验方法签名 |
| `MqttMessageRouter` | 接收 MQTT 消息，根据 Topic 匹配 Handler，通过反射调用 |
| `MqttTopicMatcher` | 实现 MQTT Topic 通配符匹配（`+` 单层、`#` 多层） |
| `MqttHandlerMethod` | 封装 Handler 的 Bean 实例、Method 对象、Topic 模式 |

#### 5.11.3 消息流转流程

```
MQTT Broker 推送消息
       │
       ▼
MqttPahoMessageDrivenChannelAdapter（入站适配器）
       │
       ▼
messageInboundChannel（DirectChannel）
       │
       ▼
MqttMessageRouter.route(message)
       ├── 提取 mqtt_receivedTopic + payload
       ├── 调用 MqttHandlerMethodRegistry.findHandler(topic)
       ├── buildArguments() 构建方法参数
       │     ├── @MqttTopic → 注入 topic 字符串
       │     ├── @MqttPayload → FastJSON2 反序列化
       │     ├── Message 类型 → 注入原始 Message
       │     └── 未标注 String → 按顺序注入 topic / payload
       └── method.invoke(bean, args) 反射调用
```

#### 5.11.4 消息发送

通过 `MqttGateway`（`@MessagingGateway`）声明式发送：

```java
@MessagingGateway(defaultRequestChannel = "mqttOutboundChannel")
public interface MqttGateway {
    void sendMsgToMqtt(@Header(MqttHeaders.TOPIC) String topic, String payload);
    void sendMsgToMqtt(@Header(MqttHeaders.TOPIC) String topic,
                       @Header(MqttHeaders.QOS) int qos, String payload);
}
```

1. **公开页面**：`meta.public: true` 的页面直接放行（导航页、登录页、大屏、Demo 页）
2. **Token 校验**：需登录页面检查 `userStore.token`，无 Token 则跳转登录页
3. **角色校验**：检查 `userStore.roles` 是否包含路由 `meta.roles` 中的任一角色

角色定义：

| 角色 | 可访问模块 |
|------|-----------|
| `admin` | 全部模块 |
| `device_admin` | 设备管理 |
| `product_admin` | 产品管理 |
| `hr_admin` | 人事管理 |

| 面板组件 | WebSocket Topic | 展示内容 |

## 8. API 接口文档

### 8.1 统一响应格式

所有 REST API 统一返回 `Result` 格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": 1722153600000
}
```

分页接口返回 `PageBean`：

```json
{
  "code": 200,
  "message": "获取列表成功",
  "data": {
    "total": 100,
    "list": [...]
  }
}
```

### 8.2 鉴权说明

- 除 `/api/pm/login` 外，所有 `/api/**` 接口需要在请求头携带 `Authorization` 字段，值为 JWT Token
- 登录成功后返回 Token，前端通过 Pinia 持久化存储
- Token 过期或无效时返回 `{"code": 401, "message": "Authorization无效"}`
- 前端 Axios 响应拦截器检测 401 后自动清除 Token 并跳转登录页

## 9. MQTT 通信设计

### 9.1 MQTT Topic 设计

#### PLC 设备相关

| Topic | 方向 | 说明 |
|-------|------|------|
| `order/service/switch` | 设备 → 服务端 | PLC 开关状态上报 |
| `order/service/sync` | 设备 → 服务端 | PLC 同步数据上报 |
| `order/service/control` | 服务端 → 设备 | PLC 控制指令下发 |

#### 传感器实验箱相关

| Topic | 方向 | 说明 |
|-------|------|------|
| `eduBox/server/data/#` | 设备 → 服务端 | 传感器实时数据上报（通配订阅） |
| `eduBox/server/examId/#` | 设备 → 服务端 | 实验切换通知 |

### 9.2 消息格式

所有 MQTT 消息 Payload 使用 JSON 格式，通过 `@MqttPayload` 注解自动反序列化为 Java 对象。

```json
  "sensor": 25,
  "value": 28,
  "datetime": "2026-07-29T10:30:00"
}
```

**PLC 开关状态示例**：

```json
{
  "sn": "PLC-001",
  "seqNo": 1,
  "action": 1,
  "workBeginTime": "2026-07-29T10:00:00"
}
```

## 11. 开发指南

### 11.1 本地开发环境搭建

1. **启动 MySQL**：确保 MySQL 8.0+ 运行中，创建 `smartfactorydb` 数据库并执行建表脚本
2. **启动 MQTT Broker**：推荐使用 EMQX 或 Mosquitto，默认端口 1883
3. **启动后端**：`cd SmartFactoryService && mvn spring-boot:run`
4. **启动前端**：`cd SmartFactoryWeb && pnpm install && pnpm dev`
5. **访问地址**：
   - 前端开发服务器：`http://localhost:5173`
   - 后端 API：`http://localhost:8080`
   - 大屏页面：`http://localhost:5173/dashboard`

### 11.2 编码规范

**后端**：
- Controller 层只做参数校验和路由转发，业务逻辑放在 Service 层
- Service 层采用接口-实现分离，便于扩展和测试
- Mapper 层继承 `BaseMapper<T>`，使用 `LambdaQueryWrapper` 构建查询条件
- 统一使用 `Result` 和 `PageBean` 作为返回对象
- 使用 `@RestControllerAdvice` 统一异常处理，避免 try-catch 散落

**前端**：
- 使用 Composition API（`<script setup>`）编写组件
- API 调用统一封装在 `src/api/` 目录，按模块划分
- 状态管理使用 Pinia，需要跨页面共享的状态才放入 Store
- 对话框组件放在 `src/component/` 对应模块目录下
- 路由使用懒加载（`() => import(...)`）

### 11.3 Git 工作流

- 主分支：`main/master`
- 功能分支：`feature/功能名称`
- 修复分支：`fix/问题描述`
- 提交信息格式：`[模块] 简要描述`

### 11.4 添加新模块

**后端添加新模块步骤**：

1. 在 `Domain/Entity/` 下创建 Entity 类，使用 `@TableName` 映射表
2. 在 `Mapper/` 下创建 Mapper 接口，继承 `BaseMapper<T>`
3. 在 `Service/` 下创建 Service 接口和 `impl/` 实现类
4. 在 `Controller/` 下创建 Controller 类
5. 如需 MQTT 消息处理，使用 `@MqttController` + `@MqttSubscribe` 注解
6. 如需定时推送，在 `scheduler/` 下创建推送任务

**前端添加新页面步骤**：

1. 在 `src/api/` 下添加 API 调用函数
2. 在 `src/views/` 对应模块目录下创建页面组件
3. 在 `src/router/index.js` 中添加路由配置
4. 在 `src/component/` 对应模块目录下创建必要的对话框组件
